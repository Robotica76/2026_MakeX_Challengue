## Entry workflow

1. Start with objective, source-linked requirements, and alternatives.
2. Record selection and rationale before building or changing a prototype.
3. Add prototype revision, test procedure, and observed results.
4. Record problems, corrective actions, and Keep / Modify / Reject decision.
5. Link evidence and update affected design, requirements, interfaces, and verification records.

For a non-prototype decision, explain why prototype or test sections are not applicable; do not manufacture results. Use TBD for unknowns. Link [test results](../test_results/README.md), [lessons](../lessons_learned/README.md), and the [notebook index](../README.md).
